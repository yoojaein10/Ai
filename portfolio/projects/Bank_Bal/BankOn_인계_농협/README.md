# BankOn — 농협 담보 자동입력 (인계본)

감정평가 결과(`.gam` + 의견서 + APW DB)를 읽어 **BANK24 농협 담보 화면
(`TBNKNHB24DAMB`)** 에 자동입력하는 코드입니다. 농협 건만 추려 담았습니다.

- **매핑 로직은 `src/bankon/mapping/nh.py` 한 파일**입니다. 여기부터 보세요.
- 무엇을 왜 그렇게 정했는지는 **`docs/농협은행_담보_인계.md`** 에 전부 적혀 있습니다.
  화면 실측 14건 + 무인 순회 116건으로 규칙을 정했고, 근거 문서번호까지 달아 뒀습니다.

> **농협은 `농협은행`(중앙회)과 `지역·품목농협`(군자농협·서울축산농협 …)이 같은 폼을 씁니다.**
> 폼이 3변형(토지 49칸 / 건물 55칸 / 지역농협 65·71칸)이고 **수수료 계산 규칙이 다릅니다.**
> 판별은 `nh.is_local_coop()` — 감정평가표 의뢰처가 `농협은행` 으로 시작하는지로 봅니다.
> (⚠️ `NH_*` 테이블 존재 여부로 판별하면 안 됩니다 — 농협은행 건에도 `NHCerti0` 가 있습니다.)

## 1. 돌려보기

```bash
python -m venv .venv && .venv\Scripts\activate
pip install -r requirements.txt

pytest -q          # 328개 — 외부 연결 없이 도는 순수 로직 검증
```

`pytest` 만 **DB·화면 없이** 돕니다. 아래 검증 도구들은 **원천 DB 접속이 필요합니다**
(캐시된 `.gam` 추출물은 있지만, 지번·평가사·수수료는 DB 에서 옵니다).

```bash
copy .env.example .env      # DB 계정 채우기 (BANKON_* 는 비워 두어도 됩니다)

python tools/check_screen.py --bank nh        # 화면 정답지 14건과 전 필드 대조
python tools/check_nh_offline.py              # 같은 대조(농협 전용판)
python tools/check_combo_match.py --bank nh   # 우리 값이 콤보 목록에 있는가
```

표본 4건만 들어 있으므로 나머지 10건은 `추출물 없음 → 건너뜀` 으로 표시되고
합계 줄에 `캐시없음 10` 이 붙습니다(크래시가 아닙니다).

**표본 4건 실행 결과** — `✅116 ❌2 크래시 0 · 캐시없음 10` (본 저장소와 동일)

## 3. 농협 화면에서 **꼭 알아야 할 것** 5가지

1. **폼이 3변형**입니다(토지 49칸 / 건물 55칸 / 지역농협 65·71칸). 없는 칸을 채우려 들면
   `미발견` 잡음만 납니다. `nh.build()` 가 물건 종류로 분기합니다.
2. **실비 계산이 변형마다 다릅니다.** 농협은행 = 구성항목 합(부가세 없음) /
   지역농협 = 절사1000 후 ×1.1. **같은 라벨인데 뜻이 다릅니다.**
3. **라벨 없는 칸은 위치로 짚습니다** — `물건기호`~`번지구분` 사이 7칸의 구성이
   실측 15건에서 완전히 동일합니다(`nh.BOX_*` 상수, `ui/form.py` 의 `POSITIONAL` 주석).
   부동산구분·소재지·법정동코드 3칸을 이걸로 채웁니다.
4. **소재지는 공부 스캔 주소의 지번 앞까지**입니다. 문서 대표 주소(`apw_masterex.ADDR`)를
   그냥 쓰면 다물건 건에서 **다른 물건**을 가리킵니다(실측 2645: 대표=의왕시 / 화면=안양시).
   **법정동코드는 문서 단위 값 하나뿐**이라, 물건 소재지가 대표와 다르면 **비웁니다.**
5. **등기번호는 순번이 아니라 면적으로** 공부스캔 행을 고릅니다(실측 2625: 408호·409호가
   둘 다 No=3). `scan.identify()`.

> **한 가지 더** — 소스와 화면이 **우연히 같으면 규칙을 못 가릅니다.** 농협 건물구조가
> 그랬습니다: 표본 14건으론 판단 불가였고, 73건 순회에서 두 방식을 재 보고서야
> "원문 유지"가 맞다고 갈렸습니다(원문 4건 불일치 vs 통일 7건 불일치).
> **매핑을 만든 뒤 반드시 순회로 표본을 늘리세요.**

## 4. 안전장치 (그대로 유지해 주세요)
- **기본은 드라이런.** `--live` / `--fill-live` 를 줘야 실제로 씁니다.
- **빈칸만 채웁니다.** `--overwrite` 가 없으면 사람이 넣은 값을 건드리지 않습니다.
- **넣고 나서 되읽어 확인**합니다. 다르면 그 칸에서 멈춥니다.
- **콤보는 Enter 전에 표시값을 확인**하고, 목록에 없으면 **ESC 로 취소해 원래 값을 둡니다**
  (틀린 항목이 확정되는 경로가 없습니다). 실폼에서 바꿨다 되돌리기 3/3 통과했습니다.
- **저장은 사람이 합니다.** 코드가 누르는 버튼은 `찾 기`·`조 회`·`닫 기` 뿐입니다
  (`저 장` 을 누르는 경로가 없음을 전수 확인했습니다).
- 다물건 문서에서 **어느 물건인지 확신 못 하면 실입력을 보류**합니다.
- `일련번호` 는 화면이 관리하는 앵커라 **읽기만** 합니다(`form.ANCHOR_LABELS`).

## 5. 실행 환경 — 함정 둘
- Python 3.12 · Windows · SQL Server ODBC Driver 17
- **`.env` 경로는 UNC 로 적으세요**(`\\서버\공유\…`). BANK24 가 관리자 권한으로 도는데
  매핑 드라이브(`Y:`)는 로그온 세션마다 따로여서 **관리자 프로세스에는 안 보입니다**
  → `gamexport` 가 `[WinError 2]` 로 죽습니다.
- 화면에 **입력**하려면 이쪽도 관리자로 띄워야 합니다(읽기는 일반 권한으로 됩니다).
- ⚠️ **이 폴더 안에서 검증 도구를 돌리지 마세요.** `.gam` 을 FTP 로 받아 `work/` 와
  `output/` 에 쌓입니다(실제로 22.8MB 문서가 딸려 들어간 적 있습니다).
  검증은 다른 위치에 복사해서 하세요.

## 6. 남은 과제
- **빈 폼 실입력 시험** — 지금까지 조회된 건은 전부 이미 작성된 폼이라 빈칸이 없었습니다.
  아직 안 쓴 담보가 생기면 `--fill-live --select` 를 감독 하에 한 건 돌려 보세요.
- **건물명 7/73 불일치** — 화면이 꼬리를 떼고 씁니다(`은평자이더스타스퀘어`→`은평자이더스타`).
  어디까지 떼는지 규칙 미확정.
- **부동산구분 콤보 목록** — `recon_combos` 가 라벨(`물건종류`)로 모아 두 콤보가 겹칩니다.
  목록을 못 써서 화살표로 훑습니다(항목 2개라 느려지는 정도).
