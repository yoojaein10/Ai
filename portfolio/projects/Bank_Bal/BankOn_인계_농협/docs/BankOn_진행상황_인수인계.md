## 1. 다른 PC 셋업 (필수)
1. **폴더 통째로 연결** (이 저장소 전체).
2. **`.env`** — DB/FTP 접속정보, 경로. 확인 항목:
   - `SOURCE_SQL`(apworksdw, 192.0.2.10:1433) · `SCAN_SQL`(appraisal, 등기번호)
   - `FTP`(BonJisa, 192.0.2.10:21) — .gam 다운로드
   - `GAMEXPORT_EXE=Y:\PUBLIC_SOURCE\gamexport.exe` · `WORK_DIR`·`OUTPUT_DIR`
   - ※ **`Y:` 는 관리자 세션에 안 따라온다**(매핑 드라이브는 권한 상승 시 사라진다).
     관리자로 돌릴 땐 환경변수로 UNC 를 덮어써라 —
     `$env:GAMEXPORT_EXE='\\etc\JUNSAN\AI\원동하\BankOn\delphi\delphi\gamexport.exe'`
     (`load_config` 는 `override=False` 라 **환경변수가 `.env` 를 이긴다**). `WORK_DIR`·`OUTPUT_DIR` 도 같이.
3. **`gamexport.exe`** (delphi 폴더) — .gam 추출기. 있어야 함.
4. **Python 3.12** — `winget install Python.Python.3.12 --scope user` (관리자 불필요) 후
   `pip install olefile pyodbc python-dotenv pywinauto pytest`.
   `python -m pytest -q` 로 **202개 통과** 확인(환경 정상 지표).
5. **ODBC Driver 17 for SQL Server** — `winget install Microsoft.msodbcsql.17` (관리자 필요).
   레거시 `SQL Server` 드라이버만 있으면 `pyodbc` 접속이 안 된다.
6. **BANK24 실행 + 로그인** — 검증하려는 은행 담보폼/그리드 띄운 상태.
7. **BANK24 가 관리자로 떠 있으면 우리도 관리자여야 한다.** 읽기(컨트롤 열거)는 일반 권한으로
   되지만, **값을 넣거나 메뉴를 여는 순간** UIPI 가 막는다
   (`Not enough rights to use EM_REPLACESEL message`). 그때만 권한을 올려라.

### ⚠️ gamexport 날짜는 추출한 PC 의 로캘을 탄다
같은 문서가 원본 PC 에선 `2026-08-12`, 이 PC 에선 **`8/12/2026`** 로 나온다(Delphi
FormatSettings 가 시스템 로캘을 따라감). 코드가 ISO 로 정규화하지만
(`parse/outline.to_iso_date`), **다른 PC 로 옮길 때마다 날짜 칸을 한 번은 눈으로 확인**할 것.

## 2. 검증 방법 (명령어)
### 단건 검증 (화면에 해당은행 담보폼 열어둔 상태)
```
python tools/verify_fill_kb.py  01-2605-3-1638     # 국민
python tools/verify_fill_ibk.py 01-2608-3-2683     # 기업
python tools/verify_fill.py     01-2608-3-XXXX     # 신한
```
결과: `✅일치 / ❌불일치 / 🖊우리채움(화면빈칸) / 📄화면만`. **열린 폼과 문서번호가 같아야** 정확(다르면 엉뚱한 화면과 비교됨).

### 무인 그리드 순회 (전건 자동검증, 관리자 권한) — **주력 검증 수단**
```
python tools/verify_grid_loop.py --bank ibk --requery --max 150 --cleanup --log out.txt
   --bank shg|kb|ibk (신한/국민/기업)
   --requery  시작 전 '조 회'를 다시 눌러 목록 복원(단건 '찾 기' 뒤에 필수)
   --cleanup  검증 후 .gam 삭제(디스크 절약)
```
그리드를 훑으며 각 문서를 `작성(열람)`으로 열어 → 폼에서 본번지·부번지·평가사를 읽어 DB로
문서번호 역조회 → `.gam` 추출·매핑 → 화면과 필드별 대조 → 닫고 다음 행. 화면엔 쓰지 않는다.
다른 은행 폼·실사전(.gam없음)은 자동 스킵. 150행이면 20분쯤 걸린다.

> ⚠️ **도는 동안 BANK24·마우스·키보드를 건드리면 안 된다** — 그리드 포커스를 잃으면
> 엉뚱한 행을 연다. 조회조건(업무구분·기간)은 화면에 잡아 둔 그대로 쓴다.

### 오프라인 회귀검사 (라이브폼 불필요) — **매핑 고치면 먼저 이것부터**
```
python tools/check_kb_offline.py     # 국민: 캐시/다운 .gam으로 매핑 재생성 → EXPECT 대조
python tools/check_ibk_offline.py    # 기업: output/<문서> 추출물 그대로 재계산(35건, 몇 초)
python tools/check_nh_offline.py     # 농협: 화면값 정답지(recon/nh_screen.json)와 전 필드 자동대조
```
농협판이 가장 편하다 — **정답지가 파일로 있어** EXPECT 를 손으로 적을 필요가 없다.
새 은행도 이 방식을 쓰면 된다(아래 '새 은행 여는 순서').
기업판은 FTP·gamexport 없이 `output/<문서번호>/` 의 추출물을 바로 읽는다
(`gam_bridge.load_extracted`). **분리합(토지+건물+기계+기타) = 총감정평가액** 을 상시 검사한다 —
분리는 명세행, 총액은 `gam_info.price` 라 서로 다른 소스여서, 맞으면 물건행이 안 샜다는 뜻이다.

### ★ 새 은행 여는 순서 (농협에서 정립 — 하나·우리도 이대로)
```
1) python tools/fetch_docs.py --bank 농협 --limit 16
      의뢰처로 실사완료 담보 표본을 골라 .gam 을 받아 추출만 한다(화면 불필요).

2) (관리자) python tools/recon_form.py <문서 14개> --values-out recon/nh_screen.json
      문서를 하나씩 열어 라벨표(recon/fields_<클래스>.md)와 **문서별 화면값**을 모은다.
      화면값이 곧 매핑의 정답지가 된다.

3) python tools/trace_values.py recon/nh_screen.json [--label <라벨> --detail]
      화면값이 **소스 어디서 오는지** 역추적한다(.gam 테이블 전 컬럼 + 개요 + 명세행 + DB).
      "경로  맞은문서수/값있는문서수" 로 나온다 — 여러 문서에서 반복해 맞으면 그게 규칙이다.

4) src/bankon/mapping/<bank>.py 작성 → python tools/check_<bank>_offline.py 로 전 필드 자동대조

5) (관리자) python tools/verify_grid_loop.py --bank <bank> --requery --max 160 --cleanup --log …
      실화면 무인 순회. 표본 14건으로는 못 갈리던 규칙이 여기서 드러난다(실측: 농협 건물구조).
```
2·5 는 **관리자 권한 필요**, 도는 동안 BANK24 를 건드리지 말 것.

> **표본이 작으면 소스와 화면이 우연히 같아 규칙을 못 가른다.** 농협 건물구조가 그랬다 —
> 14건에서는 소스·화면이 둘 다 `철근콘크리트구조` 라 "원문 표기"로 판단했는데, 73건 순회에서
> 소스 `철근콘크리트조` → 화면 `철근콘크리트구조` 4건이 나와 국민과 같은 규칙임이 드러났다.

## 3. 자동입력 현황
```
추출 → 매핑 → 순번정합 → 입력계획 → (실입력) → 사람저장
```
- **`ui/form.py`** = 입력 드라이버(라벨로 칸 찾아 set_text + 되읽기검증, **메시지기반이라 마우스 안 뺏김**). 은행 무관.
- **`tools/autofill_kb.py`(국민)·`autofill_ibk.py`(기업)** = 자동입력 CLI.
```
python tools/autofill_ibk.py 01-2608-3-2683          # 드라이런(계획만, 안전)
python tools/autofill_ibk.py 01-2608-3-2683 --live   # 실제입력(빈칸만, 연습건 먼저!)
```
- **안전장치**: 기본 드라이런 · --live도 **빈칸만 채움**(--overwrite여야 덮음) · 되읽기 불일치시 정지 · **사람이 저장**(자동제출X).
- **순번 정합**: 다물건이면 화면 감정평가액↔우리 물건 금액매칭(없으면 일련번호)으로 채울 물건 선택. **일련번호 앵커는 안 씀**. 불명확하면 실입력 보류.
- **무인 순회 채우기 은행 가드**: `verify_grid_loop --fill[-live]` 는 `FILLERS` 에 등록된 은행
  (국민·기업)만 채운다. 예전엔 은행과 무관하게 **국민 매핑**을 써서, `--bank ibk --fill-live` 가
  라벨이 겹치는 칸(본번지·소재지·감정평가액…)에 국민 값을 주입할 수 있었다.
- **폼 닫기는 포그라운드로 올린 뒤 메시지로**(set_focus → BM_CLICK). 좌표 클릭은 폼이 앞에
  없으면 **그 자리의 다른 창을 누른다** — 실제로 폼이 안 닫힌 채 다음 문서 화면값을 읽는
  사고가 났다. 뒤에 깔린 폼은 BM_CLICK 에도 반응하지 않는 경우가 있어 포커스를 먼저 준다.
  그래도 안 닫히면 예외로 멈추고, 화면에 뜬 안내창 제목을 같이 알려 준다(**우리가 누르지 않는다**).
- **라벨 없는 칸 → 위치 표기로 해결**(`ui.form.between_labels` + `POSITIONAL`).
  `소재지@물건기호~번지구분[5]` 처럼 **두 라벨 사이의 순서**로 짚는다. 절대좌표가 아니라
  창 크기가 바뀌어도 견딘다. 농협에서 소재지·법정동코드·부동산구분 3칸을 켰다(실측 15건 동일).
- **콤보 자동선택**(`--select`) — `recon/combo_<폼클래스>.md` 목록으로 순번 점프,
  Enter 전에 표시값 확인, 목록에 없으면 ESC 로 취소. **농협·기업·국민 모두 수집 완료.**
- **쓰기 전 관문 3종**(새 은행을 열 때 반드시):
  1. `check_label_targets.py --bank X --doc …` — 라벨이 **어느 칸을 짚는지**(⚠중복/✗미발견)
  2. `check_combo_match.py --bank X` — 우리 값이 **콤보 목록에 있는가**
  3. `check_combo_change.py --bank X` — 실폼에서 **바꿨다 되돌리기**가 되는가
- **아직 자동입력 안 되는 것**: 라디오·체크 자동선택 · 국민 위치 표기(정답지 수집이 먼저).
- **`.env` 경로는 UNC 로**(`\\Etc\junsan\…`). BANK24 가 관리자 권한이라 입력하려면 우리도
  관리자로 띄우는데, 매핑 드라이브(`Y:`)는 **관리자 세션에 안 보인다** → `[WinError 2]`.

### ★ 믿고쓰기 마지막 관문 (아직 안 함)
**실사완료 문서 하나에서 `--live`를 감독 하에 실행**해 실입력·되읽기검증 통과를 눈으로 확인. 통과하면 매일 `--fill-live`로 순회 가능.
> 그 전에 반드시 위 **gamexport 날짜 로캘** 항목을 확인할 것 — 정규화 전이었다면 기준시점 칸에
> `8/12/2026` 이 들어갔을 상황이었다. 연습건 `--live` 때 날짜 칸을 눈으로 볼 것.

## 5. 기업은행 매핑 상세
- 소스 = **land_list(명세표)** 기반(국민 토지와 유사, KB_*없음). 파일 `src/bankon/mapping/ibk.py`.
- **정확(항상 일치)**: 감정평가액·총감정평가액·**토지/건물/기계기구/기타 평가금액 4분리**·공부/사정면적·평가단가·본번/부번·법정동·번지구분·부동산구분·수수료(순수료·부가세·감정수수료·**실비=구성항목합 부가세X**)·기준시점·등기번호·**소재지·건물명·건물구조·전용면적·준공일자**.
- 물건유형별: 토지 ✅ / 일반건물 ✅ / 기계기구 ✅ / 선박·동산(→기타) ✅ / **집합건물 ✅(건물상세 포함)**.
- **★ `land_list` 는 `NO` 열이 물건 종류를 정한다** — 숫자=토지 필지, 한글 한 글자(가/나/다)=그
  지상 건물. 건물 블록에서는 `JIMOK`=건물용도, `YONGDO`=**건물구조**로 **열의 뜻이 바뀐다**.
  테이블 이름(land_list)으로 토지·건물을 판정하면 안 된다(`DetailRow.kind` 사용).
  land_list 뿐인데 토지가 하나도 없는 문서가 실제로 있다(2452 단독주택).
- **남은 엣지**(상세 = `output/기업은행_담보_인계.md`): 물건종류(소스 애매)·용도지역 노이즈·
  담보구분·동/호(라벨 하나에 칸 둘)·내용/잔존년수.

## 6. 파일 맵
