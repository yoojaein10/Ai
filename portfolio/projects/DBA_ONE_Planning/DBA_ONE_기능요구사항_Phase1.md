## 1. 범위

### 포함 (Phase 1)

계획서 §13.2의 8개 기능 영역: 연결·권한 검사, 객체·의존성 수집, Query Store/DMV 성능 분석, 느린 쿼리·계획 회귀·Lock 모니터링, 미사용 후보 신뢰도 분석, 프로시저 정적 분석, AI 자연어 조회, 알림·감사 로그.

### 제외 (Phase 1)

운영 DB 자동 변경, 세션 종료 실행, Oracle/PostgreSQL, 승인·배포 워크플로 실행(화면은 목업으로 검증), SQL 파라미터 값 수집.

## 2. 기능 요구사항

### FR-1 연결 및 권한 검사

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-1.1 | **[P]** MSSQL 인스턴스에 읽기 전용 진단 계정으로 연결한다. 연결 문자열·비밀은 환경변수 또는 gitignore된 설정 파일에서만 읽는다. | 필수 |
| FR-1.2 | **[P]** 연결 시 쓰기 명령을 실행하지 않고 필요 권한(VIEW SERVER STATE, VIEW ANY DEFINITION)과 Query Store 활성 여부를 점검하고 누락 항목·부여 스크립트를 안내한다. | 필수 |
| FR-1.3 | 환경 구분(개발/테스트/스테이징/운영)을 등록받고, 운영 연결은 모든 화면에 고정 배지로 표시한다. | 필수 |
| FR-1.4 | TLS를 기본 사용하고, 인증서 검증 해제는 경고와 함께 별도 승인 절차를 거친다. | 필수 |
| FR-1.5 | **[P]** DB 미연결·드라이버 부재 시 데모 데이터 모드로 동작한다(fail-closed: 어떤 경우에도 쓰기 없음). | 필수 |

### FR-2 상태 관제 (홈·모니터링)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-2.1 | **[P]** 서버 CPU·세션·요청 상태를 DMV로 수집해 대시보드에 표시한다. | 필수 |
| FR-2.2 | **[P]** 수집 시각과 데이터 신선도(지연)를 항상 표시한다. | 필수 |
| FR-2.3 | 핵심 지표를 15~60초 주기로 자동 갱신하고, 수집 부하가 임계치를 넘으면 비필수 수집을 완화한다. | 높음 |
| FR-2.4 | 시간 범위(실시간~7일)와 기준선 비교(전일·전주 동일 시간)를 제공한다. | 높음 |

### FR-3 느린 쿼리·계획 회귀 분석

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-3.1 | **[P]** Query Store에서 실행시간 상위/회귀 쿼리를 조회해 P95·호출수·논리 읽기와 함께 표시한다. | 필수 |
| FR-3.2 | **[P]** 동일 쿼리의 실행 계획 변경을 감지하고 이전 계획과 성능·주요 연산자를 비교한다(프로토타입 v0.2: 계획별 평균 실행시간 1.5배 기준 회귀 판정). | 필수 |
| FR-3.3 | 기준선(요일·시간대) 대비 이상 점수를 계산해 정렬한다. | 높음 |
| FR-3.4 | Query Store 비활성·이력 부족 시 그 사실과 진단 한계를 명시한다. | 필수 |

### FR-4 세션·Lock 모니터링

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-4.1 | **[P]** 현재 세션·요청·대기 유형을 DMV로 조회해 표시한다. | 필수 |
| FR-4.2 | **[P]** Blocking 체인을 최초 Blocker 기준 트리로 표시하고 지속시간·영향 세션 수·호출 애플리케이션을 보여준다(프로토타입 v0.2). | 필수 |
| FR-4.3 | 세션 종료는 Phase 1에서 실행하지 않는다 — 영향 분석 정보와 대안(완료 대기·배치 중단)만 제시한다. | 필수 |

### FR-5 객체·의존성·미사용 분석

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-5.1 | 테이블·뷰·프로시저·함수·인덱스 메타데이터와 정의를 수집·탐색한다. | 필수 |
| FR-5.2 | sql_expression_dependencies 기반 참조·호출 의존성을 그래프로 제공한다. | 필수 |
| FR-5.3 | 미사용 후보는 "관찰 기간 중 사용 흔적 없음"으로 표현하고 관찰 기간·수집 공백·서버 재시작·동적 SQL 가능성을 신뢰도로 환산해 표시한다. 즉시 삭제를 제안하지 않는다. | 필수 |
| FR-5.4 | 프로시저 정적 분석: 인덱스 무효화 조건, 암시적 형 변환, SELECT *, 동적 SQL, 트랜잭션 범위 등 규칙 위반을 심각도·근거와 함께 표시한다. | 높음 |

### FR-6 AI 진단 (자연어 조회)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-6.1 | **[P]** 수집된 성능 지표·쿼리 텍스트를 근거로 AI가 원인 후보와 개선 제안을 생성한다. 응답 표준: 결론→근거→원인 후보→권장 조치→신뢰도. | 필수 |
| FR-6.2 | **[P]** 외부 LLM 전송 전 SQL 리터럴(문자열·숫자)을 마스킹하고, 파라미터 값·데이터 샘플은 전송하지 않는다. | 필수 |
| FR-6.3 | **[P]** 전송되는 데이터 요약을 사용자가 확인할 수 있다(전송 미리보기). | 필수 |
| FR-6.4 | AI가 생성한 SQL은 다음 조건을 **모두** 충족할 때만 실행할 수 있다: (1) 서버측 단일 SELECT 검증(주석·리터럴 제거 후 SELECT/WITH만, 금지 명령 차단) 통과 (2) 사용자가 실행 버튼으로 명시적 승인 (3) 연결 계정에서 안전하지 않은 권한(쓰기·특권)이 감지되지 않음 — 감지 시 실행 차단(fail-closed), 모니터링·SQL 생성은 허용. DDL/DML 등 데이터·구조 변경 실행 경로는 존재하지 않아야 한다. *(v0.6에서 "실행 경로 없음"에서 "검증+승인 후 SELECT 실행"으로 정책 변경, 2026-07-21 문서 반영)* | 필수 |
| FR-6.5 | DB에서 수집한 주석·문자열 속 지시문을 시스템 명령으로 해석하지 않도록 프롬프트를 데이터 블록으로 격리한다. | 필수 |
| FR-6.6 | API 키 미설정 시 AI 기능은 비활성화되고 그 사실을 표시한다(fail-closed). **[P]** | 필수 |

### FR-7 알림·감사

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-7.1 | 임계값·기준선 기반 알림을 생성하고 동일 원인을 묶는다. 알림에는 원인 후보와 다음 행동을 포함한다. | 높음 |
| FR-7.2 | 조회·AI 질의(모델 버전 포함)·설정 변경을 감사 로그로 남기고 일반 사용자는 수정할 수 없다. | 필수 |
| FR-7.3 | 외부 채널 알림에는 SQL 본문·파라미터 값을 포함하지 않는다. | 필수 |

## 3. 보안 요구사항 (Phase 1)

| ID | 요구사항 |
|---|---|
| SR-1 | **[P]** 진단·수집용 DB 접근은 사전 정의된 파라미터 바인딩(`?`) 쿼리 allowlist로만 수행한다. 유일한 예외는 FR-6.4의 AI 생성 SELECT이며, 서버측 검증·사용자 승인·권한 게이트를 모두 통과한 경우에만 실행된다. 그 외에 사용자·AI 입력이 SQL 문자열에 삽입되는 경로가 없어야 한다. |
| SR-2 | **[P]** 비밀(연결 문자열, API 키)은 환경변수 우선, 파일 저장 시 gitignore 확인. 로그·오류 메시지·화면에 노출 금지. |
| SR-3 | **[P]** 웹 콘솔은 127.0.0.1에만 바인딩한다(Phase 1은 단일 사용자 로컬 실행). 외부 공개 시 인증 도입 전까지 차단. |
| SR-4 | **[P]** 외부 LLM 전송 데이터는 마스킹 규칙 통과 후에만 전송하고, 전송 대상 요약을 감사 기록에 남긴다. |
| SR-5 | 읽기 계정 사용을 강제한다: 연결 시 보안 토큰(sys.login_token/user_token)·유효 권한(fn_my_permissions)·권한 카탈로그·고정 역할을 검사해, 읽기 allowlist 밖 권한이 감지되면 경고를 표시하고 **AI SQL 실행을 차단**한다(판정 불가 시에도 차단). 특권 계정 연결 자체는 모니터링 목적으로 허용한다. 개발용 우회는 보호된 환경변수(`DBAONE_UNSAFE_ALLOW_PRIVILEGED_RUN=1`)로만 가능하며 감사 기록을 남긴다. 이 게이트는 위험 계정 발견 장치이며, 최종 방어선은 전용 읽기 계정(dbaone_reader)이다. |

## 4. 수용 기준 (Phase 1 완료 판정)

1. 실 MSSQL 1대에 읽기 전용 계정으로 연결해 느린 쿼리 상위 10개와 그 근거(P95·호출수·논리 읽기·관찰 기간)를 확인할 수 있다.
2. Blocking 상황을 재현하면 5초 이내 수집 주기 안에 최초 Blocker가 트리로 표시된다.
3. AI 진단 결과에 데이터 출처·관찰 기간·신뢰도가 항상 표시되고, 존재하지 않는 객체를 근거로 사용하지 않는다.
4. 코드 검토·재현 테스트(`prototype/tests/`)에서 SR-1(allowlist 외 주입 경로 없음)과 FR-6.4(검증·승인·권한 게이트 없이 실행되는 경로 없음)가 확인된다.
5. 수집으로 인한 대상 DB CPU 증가가 평균 1% 이내로 측정된다.

## 5. 프로토타입 v0.1 범위 요약

위 **[P]** 항목만 구현한다. 목적은 "실제 DB 관찰 → 마스킹 → Gemini 진단 → 근거 표시" 루프의 검증이며, UI 완성도는 목업이 담당한다.

- 실행: `python app.py` → `http://127.0.0.1:8400` (고정 URL)
- 데모 모드: DB·키 없이도 전체 흐름 확인 가능
- 실 연결: `pyodbc` 설치 + `config.json`(gitignore) 또는 환경변수
- AI: `GEMINI_API_KEY` 환경변수 설정 시 실제 Gemini 호출
