| FR-6.1~6.6 | AI 진단·마스킹·미리보기·제안전용·주입방지·fail-closed | ✅ | 실서버에서 진단 품질 검증됨 |
| FR-7.1~7.3 | 알림·감사·외부채널 마스킹 | 🔶 | 외부 채널 발송(FR-7.3)은 미구현(화면 알림만) |

**보안 요구(SR-1~5) 이행 상태 (v0.16, 2026-07-21 갱신)** — 쿼리 allowlist(? 바인딩), 비밀 환경변수·gitignore·ACL 제한, 127.0.0.1 바인딩 + 로컬 API 보호(Host·Origin·CSRF nonce·본문 제한), 외부 전송 주석 제거+마스킹+미리보기, **AI SQL 실행 권한 게이트**(안전하지 않은 권한 감지 시 차단, fail-closed). FR-6.4는 "실행 경로 없음"에서 "검증+승인+권한 게이트 후 SELECT 실행"으로 정책 변경됨(요구사항 문서 반영).

검증 근거: `prototype/tests/`의 재현 가능한 회귀 테스트(`python -m unittest discover tests`) — SQL 검증기 허용/차단, 마스킹, 실행 게이트, HTTP 보호, 연결별 이력 격리, 마이그레이션. 과거 "9개 케이스 단위테스트"는 일회성 검증이었으며 현재는 저장소 내 테스트로 대체.

## 4. 실서버에서 검증된 것

- **실 Query Store 조회**: apworksdw 느린 쿼리 실측, 계획 XML에서 연산자 자동 추출
- **AI 진단 품질**: 데모에서 "회귀"라던 프로시저를 실데이터에서 "현재 정상, CONVERT는 향후 위험"으로 정확히 구분 → 근거 없이 문제를 지어내지 않음(계획서 15.2 원칙 실증). 계획 이력을 근거로 주자 원인 지목 정확도·신뢰도 상승(90%→95%)
- **미사용 분석**: 객체 2,469개 스캔, 후보 1,370개 — APW 백업 테이블 시리즈·개인 임시 테이블 정확 검출
- **자연어 질의**: "등록이력 전체 건수" → COUNT SQL 생성·실행(40,970행). 용어집+교정 사례 축적 후 재질문 정확도 향상 실증
- **수집 부하**: 60초 주기 경량 조회로 실운영 DW에 부담 없이 동작

## 6. 미구현·한계 (본개발 이관 대상)

- **아키텍처**: 현재 단일 PC = 웹서버+수집기+저장소. 다중 사용자·24시간 운영 시 수집 에이전트 분리 + 사내 서버 콘솔 필요(계획서 9장)
- **인증·권한(RBAC)**: 현재 단일 사용자·로그인 없음. 팀 사용 시 SSO·역할별 권한 필수
- **비밀 저장**: config.json 평문. 본개발은 OS/기업 비밀 저장소로
- **정적 코드 분석(FR-5.4)**, **외부 채널 알림(FR-7.3)**, **다중 서버 동시 관제** 미구현
- **Phase 2 전체**: 프로시저 변경·테스트·승인·배포·롤백
