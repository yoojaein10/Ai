# DBA ONE 프로토타입

실제 DB 관찰 → 마스킹 → Gemini 진단 → 근거 표시 루프를 검증하는 로컬 프로토타입입니다.
설치 없이 Python 표준 라이브러리만으로 동작합니다.

## AI 챗봇 (대화형)

질문 유형을 자동 분류해 처리합니다. 이전 대화를 기억하므로 후속 질문이 가능합니다(↺ 버튼으로 초기화).

| 경로 | 예시 질문 | 동작 |
|---|---|---|
| 데이터 조회 | "이번 달 접수 건수는?" | 관련 테이블 선정 → SELECT 생성 → 사용자가 실행 버튼을 눌러야 로컬 실행 |
| 객체 질문 | "어제 새로 생긴 테이블 있어?" | sys.objects 카탈로그(이름·생성/수정·크기)로 바로 답변 |
| 상태 상담 | "지금 DB 상태 어때?" | 모니터링 요약(느린 쿼리·블로킹·알림, SQL 마스킹)으로 답변 |

- `코드가 뭐야`, `주소 찾아줘` 같은 값 조회는 데이터 경로를 우선하며, 레거시 컬럼의
  의미가 불명확하면 추측 대신 필요한 컬럼 매핑을 구체적으로 질문합니다.
- 사용자가 `X가 Y 테이블이다`라고 알려주면 자동 학습하지 않고 용어집 입력안만 제시합니다.
  사용자가 검토·수정해 저장한 내용만 이후 검색에 사용됩니다.
- 용어집과 실행·교정 사례는 `target_id`별로 분리됩니다. 현재 DB 지식과 사용자가
  명시적으로 `공통` 지정한 용어만 사용하며 다른 DB의 지식은 검색·AI 문맥에 넣지 않습니다.
  구버전의 무귀속 항목은 자동 사용하지 않고 화면에서 확인 후 현재 DB로 가져옵니다.
- 승인한 조회 결과가 1행 1열이면 외부 AI 재호출 없이 로컬 화면에서 값으로 강조합니다.

## 실행

```
python app.py
```

→ 브라우저에서 **http://127.0.0.1:8400** (고정 주소, 127.0.0.1 전용 바인딩)

## 3가지 모드

| 모드 | 조건 | 동작 |
|---|---|---|
| 데모 (기본) | 아무 설정 없음 | 샘플 데이터로 전체 흐름 확인 (마스킹·미리보기 포함) |
| AI 활성 | 환경변수 `GEMINI_API_KEY` 설정 | 실제 Gemini 진단 (데모 데이터로도 가능) |
| DB 실연결 | `pip install pyodbc` + 연결 문자열 설정 | 실제 MSSQL DMV·Query Store 조회 (읽기 전용) |

### Gemini 켜기 (PowerShell)

```powershell
$env:GEMINI_API_KEY = "발급받은키"
python app.py
```

### MSSQL 연결 (선택)

```powershell
pip install pyodbc
copy config.example.json config.json   # mssql_conn 채우기 (읽기 전용 계정 사용)
python app.py
```

## 보안 설계 (기능요구사항 SR-1~5 대응)

- 진단·수집용 DB 접근은 `app.py`의 `QUERIES` allowlist(고정 SQL + `?` 바인딩)만 사용
- **AI 생성 SQL 실행 정책 (FR-6.4)**: 서버측 단일 SELECT 검증 통과 + 사용자 승인 버튼 + **권한 게이트** 3중 조건에서만 실행. 연결 계정에서 안전하지 않은 권한(쓰기·특권)이 감지되면 실행 차단(판정 불가 시에도 차단) — 모니터링·SQL 생성은 계속 동작. 이 게이트는 발견 장치이며 최종 방어선은 전용 읽기 계정(dbaone_reader)
- AI가 생성한 SQL은 로컬 검색으로 제공된 후보 테이블 범위도 검사하며, 허구 객체·다른 DB·시스템 객체를 참조하면 실행 버튼 전에 차단
- 권한 판정: `sys.login_token`/`sys.user_token`(Windows 그룹·중첩 역할 포함) + `fn_my_permissions`(서버·DB) + 권한 카탈로그(스키마·객체 수준) + 고정 역할 검사, 읽기 allowlist 방식
- 개발용 우회는 `DBAONE_UNSAFE_ALLOW_PRIVILEGED_RUN=1` 환경변수로만 가능 (시작·실행 시 감사 기록)
- 로컬 API 보호: Host·Origin 검증, 프로세스별 CSRF nonce(모든 POST 헤더 검증), `application/json`만 허용, 본문 64KB 제한, Sec-Fetch-Site 보조 신호
- 비밀은 환경변수 우선, `config.json`은 gitignore + ACL 제한 — 로그·화면·오류에 키 미노출. 챗봇 감사 로그에는 질문 원문 대신 설치별 HMAC만 기록
- 외부 전송 전 SQL 주석 제거 + 리터럴 마스킹, 전송 미리보기(성능 분석), audit.log 기록
- 챗봇 외부 전송 범위: 질문·대화 맥락·객체 이름/생성일·마스킹된 SQL 구조 + (프로시저 진단 시) 해당 객체 소스 — 데이터 값·조회 결과는 미전송
- 시계열·알림·정의 버전은 연결 대상(target_id, 서버가 보고한 정체성)별로 분리 저장 — 서버 전환 시 데이터 혼합 없음
- 최근 대화 문맥은 서버 메모리에만 유지하며 새 대화·연결 변경 시 삭제. 실행 확인된 재사용 사례는 질문의 흔한 식별자와 SQL 리터럴을 마스킹한 뒤 `target_id`와 함께 로컬 `knowledge.json`에만 저장하고 결과 행은 저장하지 않음
