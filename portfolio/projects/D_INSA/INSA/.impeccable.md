# .impeccable.md

이 파일은 `/impeccable` 디자인 스킬이 모든 작업에서 기준으로 삼는 **디자인 컨텍스트**입니다. 수정이 필요하면 `/impeccable:impeccable teach`를 다시 실행하거나 이 파일을 직접 편집하세요.

## Design Context

### Users

**주 사용자(80% 사용 시간): 인사팀 HR_ADMIN — 하루 종일 상주 사용자**
- 화면을 닫지 않은 채 수백 건의 인사/근태/평가 레코드를 연달아 처리.
- 평가 시즌·월말·발령 시기에는 마우스보다 키보드가 빠름. 한 번의 실수가 법적·인사적 분쟁으로 번질 수 있는 작업(발령, 평가 등급 조정, 급여 연계 데이터).
- 하루 8시간 이상 같은 UI를 응시 → 시각적 피로 누적이 제품 경쟁력.

**보조 사용자(주간~월간): 부서장(DEPT_HEAD), 일반 직원(EMPLOYEE)**
- 평가 시즌·결재·본인 정보 조회 등 **단발성 방문**. 학습 부담 최소화와 직관적 탐색이 중요.
- 연령대가 넓음(20대 신입~60대 임원) → 중간 이상의 판독성 필요.

**사용 맥락**
- 대부분 **사무실 데스크톱**(1920×1080, 듀얼 모니터도 흔함), 실내 조명, 장시간 좌식.
- 한국어 단일 언어(ko_KR). 회사명 "Daehwa".
- 내부 전용 시스템, 외부 고객 노출 없음.

### Brand Personality

**세 단어: 따뜻 · 사람 중심 · 실용**

"USTRA HR"로 대변되는 한국형 그룹웨어의 무미건조한 엔터프라이즈 톤을 **벗어나되**, 스타트업 HR SaaS(Rippling/Gusto)의 지나치게 캐주얼한 이모지·일러스트 남용 또한 회피. 그 사이 어딘가 — **"정중하지만 차갑지 않은"** 지점.

**표현 축**
- 정보 밀도는 Linear/Notion처럼 절제됨. 눈이 쉽게 쉰다.
- 시각적 온도는 Rippling처럼 사람의 얼굴과 이름이 먼저 보인다. 아바타, 이름, 부서가 데이터의 중심.
- 어조는 Notion처럼 간결하되 지시문이 아니라 안내문("저장했어요", "아직 제출 전이에요" 식).

### Aesthetic Direction

**Theme: 라이트 중립(미세 웜 틴트 허용)**
- 사용자는 "순 중립 라이트"를 선호. 순수 그레이(chroma 0)는 청색으로 읽히는 경향이 있어, `chroma ≤ 0.003`의 극미세 웜 틴트로 "차갑지 않은 중립"을 만든다. 시각적으로는 "그냥 중립"으로 보임.
- 다크 모드는 이번 반복에서 **지원하지 않음**. 향후 요청 시 별도 토큰 세트로 추가.

**Brand Color (유지)**
- **Navy Primary**: 현재 헤더색 `#1a1a2e` 계열 유지 → OKLCH로 표준화: `oklch(15% 0.04 275)`.
- 헤더 배경 + Primary 버튼(고빈도 이지만 이지만 아니기에 절제)에만 사용. 강조 남용 금지.
- **Accent Warm** (사람 중심 온도를 전달하는 보조색): `oklch(72% 0.13 75)` 앰버. 아바타 이니셜 배경, 빈 상태 일러스트, 알림 뱃지에만 제한.
- **Destructive**: `oklch(55% 0.15 25)` 저채도 레드. 플래시하지 않음.
- **Success**: `oklch(60% 0.12 145)` 무광 그린.
- **Surface(배경)**: `oklch(98.5% 0.002 85)` — 거의 흰색이나 미세 웜.
- 모든 뉴트럴은 h=265(Navy의 hue)로 극미세 틴트해 브랜드와 잠재적 응집.

**Typography** — 반사적 선택("Pretendard", "Noto Sans KR", "Spoqa Han Sans") 배격. 한글 + 라틴 모두 지원하며 "따뜻·사람 중심" 방향에 부합하는 조합:

- **Body / UI 전역**: **Wanted Sans Variable** — 원티드랩 오픈소스, humanist 한글 산세리프. Pretendard보다 따뜻하고 UI용 hinting이 세밀. `font-feature-settings: "tnum" 1`로 테이블 숫자 정렬.
- **Display (페이지 제목 · 빈 상태 헤드라인)**: **Gowun Dodum** — Google Fonts 제공, 둥근 humanist 한글 faces. "사람 중심" 온도를 페이지 진입 순간에 전달. 본문에는 사용 금지.
- 두 서체 모두 `reflex_fonts_to_reject` 목록에 없음. 한글 특화.
- 스케일: 앱 UI는 **고정 `rem` 모듈 스케일 1.25 비율**(fluid clamp는 H1만), 대시보드/테이블 본문 `14px/1.5`, 숫자는 `tabular-nums`.

**Spatial / Density** — 고밀도 + 섹션 간 호흡.
- 4pt 시맨틱 스페이싱 토큰(`--space-xs:4, --space-sm:8, --space-md:12, --space-lg:16, --space-xl:24, --space-2xl:32, --space-3xl:48, --space-4xl:64, --space-5xl:96`).
- AntD 컴포넌트는 `size="small"` 기본, 테이블 row 32px, form 입력 높이 32px.
- 그러나 **페이지 섹션 간엔 24~32px 여백** 확보 — 촘촘함과 답답함의 차이.
- 카드 남용 금지. 페이지 최상위는 제목 + 필터 + 단일 테이블(또는 폼). 보조 패널은 우측/하단 붙임.

**Page Grammar (실수 방지를 위한 고정된 구조)** — 모든 화면은 동일 문법:
1. **Page Header**: 페이지 제목(Display face) + 주요 액션(우측 정렬) + 파비듬 컨텍스트(회차·기간 등).
2. **Filter / Toolbar**: 상단 고정(`position: sticky; top: header`), 필터 변경 즉시 결과 반영 / 명시적 "조회" 버튼은 서버 부하 높은 조회에만.
3. **Primary Content**: 테이블 또는 폼. 화면 폭의 60~75%.
4. **Context Panel (옵션)**: 우측 또는 하단. 상세, 로그, 도움말.

어느 화면에서도 "필터가 어디 있지?"를 묻지 않게 한다.

**Motion** — 과한 모션 금지(하루 종일 쓰는 사람에게 과잉 모션은 고문). 페이지 진입 스태거 없음, 필수 피드백만:
- 저장 성공: 토스트 fade 180ms.
- 드로어/모달: slide 200ms `cubic-bezier(0.2, 0, 0, 1)` (ease-out-quart).
- `prefers-reduced-motion`에서는 transform 제거, opacity만.

**Interaction**
- Cmd-K 레벨의 전역 명령 팔레트(페이지 이동·"OOO 인사정보 열기"·"OOO 승인"), Phase 2에서 도입.
- 수정 난만한트(unsaved changes) 시 브라우저 beforeunload + 사이드바 클릭 시 컨펌.
- 파괴적 액션(삭제, 발령 취소, 등급 확정)은 **타이핑 확인**(레코드 식별자 재입력) 후 실행.
- 버튼 계층: `Primary(navy)` 1개 + `Default(ghost)` + `Text` 링크. 모든 버튼이 primary인 화면 금지.

**레퍼런스 / 안티레퍼런스**
- **따를 것**: Rippling(사람 얼굴 중심), Linear(절제된 데이터 밀도), Notion(안내 문구 톤), Workday(엔터프라이즈 신뢰).
- **피할 것**: USTRA HR·한국형 그룹웨어의 빽빽한 색띠·중첩 탭·무지개 뱃지. 공공포털 스타일의 테두리/레이블 남발.

**Absolute Bans (impeccable 공통 + 프로젝트 재확인)**
- 카드/알림/콜아웃에 `border-left: 2px+ solid <any>` 색 스트립 — **금지**. AntD Alert의 기본 좌측 액센트도 토큰으로 제거.
- `background-clip: text` + 그라디언트 텍스트 — **금지**. 현재 헤더 "Daehwa" 로고가 이 패턴에 해당하므로 셸 재설계 때 제거 1순위.
- 퍼플-투-블루 그라디언트, 다크 배경의 네온 액센트, 글래스모피즘 장식 — 모두 금지.
- 동일 크기 카드 그리드 나열식 대시보드 — 금지. 통계 화면도 표/차트의 의미에 따라 비대칭 배치.

### Design Principles (프로젝트 전반 5원칙)

1. **Grammar over Novelty** — 모든 화면은 동일한 구조 문법(Header → Toolbar → Primary → Context)을 따른다. 새 화면을 만들 때 "이 화면은 특별하니 다르게" 금지. 일관성이 실수 방지의 1순위 조건.

2. **Density with Air** — 행·셀은 촘촘히(`size="small"`, row 32px), 섹션 간은 넉넉히(24~32px). 촘촘함은 정보량을, 호흡은 위계를 전달.

3. **Warmth in the Seams, Neutrality in the Field** — 본문·표·폼은 중립 회색. 온도는 아바타·빈 상태·마이크로카피·성공 토스트 같은 "이음새"에만 얹는다. 면 전체를 따뜻하게 칠하지 않는다.

4. **Loud Primary, Quiet Destructive** — Primary(navy)는 화면당 1회, 확실히 보이게. Destructive(삭제·취소·등급 변경)는 저채도·작은 글자·타이핑 확인. "빨갛고 크게"가 아니라 "조용하되 돌이킬 수 없게".

5. **Keyboard ≥ Mouse for Power Users** — 키보드 탐색 동선은 마우스보다 빠를 것. Tab 순서 의도적 설계, 단축키, 스티키 헤더, 벌크 선택을 1급 시민으로.

## 기술 제약

- React 18 + TypeScript + Vite, **Ant Design 5 유지** — 셸(MainLayout, Header, Sider)과 핵심 대시보드만 커스텀. 테이블·폼·모달은 AntD 그대로.
- ConfigProvider `theme` 토큰으로 AntD 전역 재설정(색·radius·fontFamily).
- 한국어 전용, `@antd/locale/ko_KR`.
- 접근성: **WCAG AA를 내부 목표로 진행**(명시적 법적 요구 없음). 대비 4.5:1, 키보드 네비게이션, `prefers-reduced-motion` 존중.
