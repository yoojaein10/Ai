### 보고월 판단

업무실적의 귀속월은 `APW_IW_INDATE.INDATE`를 기준으로 판단한다.
`Writedate`는 행을 입력한 날짜이므로 보고월 선정 조건으로 사용하지 않는다.

예:

- 감정서번호: `01-2601-5-0003`
- `APW_IW_INDATE.INDATE`: 2026-04-13
- `APW_IW_INDATE.Writedate`: 2026-05-07
- `Apw_Mae_GaPrice.In_Date`: 2026-04-13
- 엑셀 보고월: 5월

이 행처럼 원본 엑셀의 월과 현재 DB의 `INDATE`가 다른 사례가 있으므로,
원본 파일 생성 당시와 현재 데이터가 달라졌는지 또는 엑셀 포함 기준에
발송월 등 다른 조건이 추가됐는지는 별도로 확인해야 한다.

`Writedate`가 5월이라는 사실은 입력 시점을 보여줄 뿐이며 실적 귀속월의
근거로 사용하지 않는다.

## 4. 권장 사용 방식

### 사용하면 안 되는 방식

```text
Apw_Mae_GaPrice.In_Date가 선택 월인 행만 조회
→ APW_IW_INDATE 모집단 전체와 같다고 간주
```

이 방식은 실적 미배분 건과 GaPrice 미생성 건을 누락시킨다.

### 권장 방식

```text
1. APW_IW_INDATE.INDATE 및 기존 APWorks 포함·제외 규칙으로 보고 대상 선정
2. Apw_Mae_GaPrice.In_Date는 APW_IW_INDATE.INDATE와 교차 검증
3. Apw_Mae_GaPrice는 담당자별 배분·귀속 수수료 보강에 사용
4. apw_masterex와 APW 보조 테이블에서 엑셀 본문 필드 생성
5. 누락·불일치 건은 검증 목록으로 표시
```

`Apw_Mae_GaPrice`는 다음 용도로는 적합하다.

- 담당자별 실적 배분
- 담당자별 순수수료
- 성과상여 계산
- `APW_IW_INDATE`와 날짜가 같은지 교차 검증

`Apw_Mae_GaPrice.In_Date` 자체는 겹치는 자료에서
`APW_IW_INDATE.INDATE`와 거의 동일하므로 날짜 의미는 대체 가능하다.
다만 GaPrice에 없는 감정서가 많아 협회 업무실적 전체 모집단을 단독으로
대체하는 용도로는 적합하지 않다.

## 6. `GamJunDW.a10_voucher_cache` 입금일 기준 대안

원본 엑셀을 입금 기준으로 만들 수는 있다. 다만 이 경우 보고서의 의미는
`INDATE` 기준 업무실적이 아니라 **완납 기준 수금실적**으로 바뀐다.

부분입금을 제외하려면 단순히 `last_received_date`가 해당 월인지 보면 안 된다.
감정서번호별 전표를 날짜순으로 누적하여 청구액을 처음 충족한
`voucher_date`를 완납일로 사용해야 한다.

권장 판정 규칙:

1. `a10_voucher_cache.management_no`로 감정서별 입금 전표를 묶는다.
2. 청구액은 전표 집계 청구액을 우선 사용한다.
3. 전표 집계 청구액이 0인 직접매출 예외는 `apw_masterex.청구금액`을 사용한다.
4. 누적 입금액이 청구액에 미달하면 부분입금으로 보고 출력에서 제외한다.
5. 누적 입금액이 청구액을 처음 충족한 `voucher_date`를 완납일로 사용한다.
6. 완납 뒤 추가 입금이 있을 수 있으므로 `MAX(voucher_date)` 또는
   `a10_receivable_summary.last_received_date`를 그대로 완납일로 사용하지 않는다.

원본 엑셀 128건 재검증 결과:

| 구분 | 건수 |
|---|---:|
| 완납 | 102 |
| 부분입금 | 2 |
| 미입금·입금전표 없음 | 24 |
| 2026년 5월에 처음 완납 | 99 |
| 2026년 6월에 처음 완납 | 2 |
| 2026년 3월에 처음 완납 | 1 |

제외해야 할 부분입금 2건:

- `01-2601-5-0003`: 전표 청구액 11,000,000원 / 입금액 5,500,000원
- `01-2604-4-0163`: 전표 청구액 1,821,600원 / 입금액 1,621,600원

주의 사례:

- `01-2603-4-0100`은 최초 완납일이 2026-03-31인데 추가 입금 때문에
  `last_received_date`가 2026-05-15이다. 마지막 입금일만 사용하면 5월 실적으로
  잘못 포함된다.
- `01-2512-3-4131`은 전표 집계 청구액이 0인 직접매출 예외지만,
  `apw_masterex.청구금액` 2,029,500원과 실제 입금액이 같으므로
  2026-05-08 완납으로 판정한다.

결론적으로 입금 기준 엑셀을 만들 때의 2026년 5월 대상은 **99건**이다.
기존 128건짜리 `INDATE` 기준 엑셀과 같은 모집단은 아니므로 보고서에서
`업무실적`과 `수금실적`을 구분해 표시해야 한다.

## 7. 공적업무 발송 기준과 `SP_YJI_JunKais_Chk`

`apworksdw.dbo.SP_YJI_JunKais_Chk`는 공적업무를 등록하거나
`APW_IW_INDATE`를 수정하는 프로시저가 아니다. 감정서번호를 받아
`Jun_Master.PCODE`가 대상 코드인지 검사하고 `Cnt`만 반환한다.

2026-02-27 이후 발송된 주택도시보증공사 건은 별도 코드 집합을 사용한다.

```text
5A, 97, 46, 33
```

그 외 건은 다음 코드 범위를 공적업무로 판정한다.

```text
21~27
31~3C (39, 3A 제외)
62~67
72, 75, 76, 77, 92, 93, 95, 9C, 9E, 9H, 9I
```

DB 저장 프로시저·함수 안에서는 이 프로시저를 호출하는 객체가 확인되지
않았다. 따라서 APWorks 클라이언트가 발송 시 직접 호출하여 반환된 `Cnt`로
업무실적 포함 여부를 판단하는 구조로 보인다.

원본 엑셀 128건과 재대조한 결과:

| 구분 | 건수 |
|---|---:|
| `APW_IW_INDATE`에 존재 | 108 |
| `APW_IW_INDATE`에 없음 | 20 |
| 누락 20건 중 프로시저 공적업무 판정 | 18 |
| 위 18건 중 APW 발송일이 2026년 5월 | 15 |
| 프로시저 범위 밖이지만 5월 발송된 법원경매 | 1 |

`APW_Master.SendDate`만 사용하면 다음과 같이 원본 128건 중 124건이
설명된다.

```text
2026년 5월 APW_IW_INDATE 대상 108건
+ APW_IW_INDATE에는 없지만 2026년 5월 발송된 16건
= 124건
```

나머지 4건은 원본 시트의 마지막 네 행에 별도로 추가된 과월 발송 건이다.

- `01-2604-3-1193`: APW 발송일 2026-04-17
- `01-2509-B-0048`: APW 발송일 2026-01-30
- `01-2603-1-0104`: APW 발송일 2026-04-30
- `01-2603-1-0231`: APW 발송일 2026-04-13

이 중 `01-2604-3-1193`과 `01-2603-1-0104`는
`Jun_Master.SendDate`가 각각 2026-05-15와 2026-05-04라서
공적업무 시스템 발송일 기준으로는 5월 편입을 설명할 수 있다.
나머지 2건은 현재 DB 날짜만으로는 5월 자동 편입 근거가 확인되지 않아
수기 보정 또는 당시 데이터 상태를 별도 확인해야 한다.

따라서 공적업무의 월 판정에 `Jun_Master.SendDate`를 우선 사용하면
원본 128건 중 **126건**까지 자동으로 설명되고, 남는 수기 보정 대상은
2건이다.

업무실적 자동화 권장 모집단:

```text
1. 일반업무: APW_IW_INDATE.INDATE가 대상 월인 건
2. 공적업무: SP_YJI_JunKais_Chk 규칙에 해당하고
   `Jun_Master.SendDate`가 대상 월인 건
3. 법원경매 등 별도 발송 기준 업무: 추가 업무코드 규칙으로 포함
4. 과월 보정: 별도 조정 테이블에서 명시적으로 포함
5. DocID가 400으로 시작하는 건은 제외
```
