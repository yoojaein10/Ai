# A10BRIDGE 작업 메모

작성일: 2026-07-17

## 현재 실행 상태

- 프로젝트: `D:\AI\A10BRIDGE`
- 서버: `http://localhost:8010`
- 감정서/전표 화면: `http://localhost:8010/dashboard`
- 입금/미수금 화면: `http://localhost:8010/receivables`
- 업무 DB: `GamJunDW`
- 감정서 원본: `[apworksdw].dbo.apw_masterex`
- Amaranth 전표 캐시: `GamJunDW.dbo.a10_voucher_cache`
- 테스트: 11개 통과
- `.env`의 토큰, 해시키, DB 암호 등 민감정보는 이 문서에 기록하지 않음

## 감정서/전표 화면 구현 내용

- 본사 건만 조회: `Office = '10'`
- 기본 접수일 범위: 최근 7일
- 검색 조건 분리:
  - 감정서번호: `DocID`
  - 소재지: `Address`
  - 거래처명: `CustName`
  - 유치자: `Manager`
  - 조사자: `Charge`
- 감정서번호가 입력되면 접수일 범위를 무시하고 과거 전체에서 검색
- 목록 표시 항목:
  - 감정서번호, 접수일, 소재지, 거래처명, 유치자, 조사자
  - 진행상태, 발송일, 평가액(`price`), 기초수수료, 여비
- 목록 클릭 시 관리번호(`ctNb`)와 `DocID`가 같은 Amaranth 전표 표시
- 전표 상세는 계정, 전표일자, 차변, 대변, 전표번호와 합계를 표시
- 부가세 라인을 포함하도록 같은 전표일자/전표번호의 전체 라인을 함께 조회

## 전표 캐시 및 성능

- Amaranth 조회 결과를 `GamJunDW.dbo.a10_voucher_cache`에 동기화
- 확인 당시 캐시 약 25,230라인, `01-` 관리번호 감정서 449건
- 감정서 상세 조회는 캐시 기반으로 빠르게 동작
- 입금/미수금 기본 목록은 캐시에서 먼저 페이지를 만든 후 해당 30건만 `apw_masterex`에서 보강
- 입금 목록 약 0.29초, 미수금 목록 약 0.19초 확인

## 입금 및 미수금 화면

- 별도 화면 `/receivables` 구현
- `입금된 목록`, `미수금 목록` 탭 제공
- 감정서번호 및 거래처명 검색
- 표시 항목:
  - 감정서번호, 거래처명, 소재지, 유치자, 접수일
  - 최근 입금일, 청구액, 입금액, 미수금, 상태
- 행 클릭 시 오른쪽에서 연결된 매출/입금 전표 상세 확인
- 현재 계산 규칙:
  - 청구액 = 외상매출금(`1080000`) 차변 합계
  - 입금액 = 외상매출금(`1080000`) 대변 합계
  - 미수금 = 청구액 - 입금액
  - 외상매출금 대변이 있으면 입금 목록
  - 청구액이 입금액보다 크면 미수금 목록
- 확인 당시 입금 관리번호 69건, 미수금 77건

## 확인된 회계 의미

다음 전표는 입금이 아니라 매출/청구 발생이다.

```text
차변 외상매출금
대변 감정수수료
대변 부가세예수금
```

실제 입금/정산 전표는 보통 다음 형태다.

```text
차변 보통예금
대변 외상매출금
```

현재 캐시에서 외상매출금 대변 라인에도 감정서 관리번호가 들어간 사례를 확인했으므로 감정서별 입금 연결이 가능하다.

주의 사례: `01-2511-3-3832`는 같은 전표에 동일 금액의 외상매출금 대변 라인이 두 줄 존재했다. 정상적인 분할 처리인지 중복인지 재무팀 확인 필요.

## APWorks 자동 전표 Outbox

- 테이블 생성 완료: `GamJunDW.dbo.a10_voucher_outbox`
- APWorks가 발송 완료 시 `DocID`와 발송 이벤트를 INSERT하는 구조
- 연동 예시: `docs/APWORKS_OUTBOX.md`
- 기본 상태: `PENDING`
- `event_id` 고유키로 중복 생성 방지
- 아직 A10BRIDGE의 Outbox 작업자와 실제 자동 전표 생성은 구현하지 않음

## 다음 주 재무팀에 확인할 내용

1. 감정서 한 건당 최초 매출전표를 하나만 생성하는가?
2. 재발송, 수정전표, 취소전표가 생길 수 있는가?
3. `event_id`를 `DocID`만으로 사용할지, 발송이력 PK까지 조합할지?
4. 입금 처리 시 외상매출금 라인에 관리번호(`DocID`)를 항상 입력하는가?
5. 한 번의 입금으로 여러 감정서를 정산할 때 감정서별 라인을 나누는가?
6. 부분입금, 과입금, 환불, 취소는 어떤 전표 규칙으로 처리하는가?
7. `01-2511-3-3832`의 동일 외상매출금 대변 두 줄은 정상 처리인가?
8. 자동 생성할 전표의 계정과 금액 규칙:
   - 외상매출금
   - 감정수수료
   - 부가세예수금
   - 기초수수료 및 여비 처리 방식
9. 세금계산서는 매출전표 저장과 동시에 자동 발행되는가, 별도 발행 절차인가?
10. Amaranth에서 세금계산서 발행상태와 승인번호를 조회할 수 있는 API 권한이 있는가?

현재 동기화한 회계 전표에는 부가세예수금 라인은 보이지만, 이것만으로 세금계산서 실제 발행 여부를 판정하지 않는다. 세금계산서 발행상태/승인번호 데이터 또는 별도 API 연동이 필요하다.
