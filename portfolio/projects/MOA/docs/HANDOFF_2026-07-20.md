## 오늘 한 일

### 1. 서버 이전 (192.0.2.10 → 192.0.2.10)

구 서버에서 Amaranth(`fin.dhapp.co.kr` = 192.0.2.10:443)가 **타임아웃**으로 막혔다.
- 구 서버 공인 IP `192.0.2.10` — 목적지와 같은 대역(분당 더존 IDC)
- ping은 0ms로 응답하나 TCP 443만 무응답 → 출발지 IP 기준 접근 통제로 추정
- 개발 PC(공인 IP `192.0.2.10`)는 정상 → 그 대역의 `192.0.2.10`로 서버 이전
- 이전 후 Amaranth 거래처 조회 실제 성공 확인. **더존에 IP 등록 요청 불필요해짐**

### 2. 신규 테이블 3개 (DB에 이미 반영됨)

- `a10_office_map` — 지사 ↔ 감정서번호 접두사 ↔ Amaranth 회계단위. 18개 지사 시드 완료
- `a10_user_permission` — 지사 사용자에게 전체 조회를 예외 허용할 때 INSERT
- `a10_access_log` — EXE 실행(사용자 컨텍스트 조회) 감사 로그

지사↔접두사 매핑(APWorks 채번 프로시저 기준): 10→01, 11→05, 12→06, 13→10, 14→11, 15→04,
16→07, 17→03, 18→02, 19→08, 21→12, 22→09, 23→13, 24→14, 25→15, 26→16, 27→17, 28→18 (구제주 20 폐기)

**본사 회계단위는 `1000`이다.** (초기에 4210으로 알고 있었으나 실데이터 대조 결과 오류 — 4210은 사용자 ID였음)

### 3. 사용자 컨텍스트

- `GET /api/users/{usr_id}/context` — `TMWCMN_USR_BAC_INFO` 검증 후 이름·지사·권한 반환
- 판정 규칙(실데이터 확인): `USE_YN='Y'` **그리고** `RTRM_FL='0'`(재직)만 허용. 그 외는 차단
- 본사(OFFICE_ID='10')는 전체 지사 조회, 그 외는 자기 지사 고정
- 성공·실패 모두 `a10_access_log`에 기록

### 4. 지사별 조회

`app/services/receivables.py`의 하드코딩 4곳(`'01-%'` 2곳, `Office='10'` 2곳)을 파라미터화.
부수 효과로 **타지사 감정서의 입금상태가 전부 '미확인'으로 나오던 버그도 해결**됐다.

### 5. thin EXE 전환

- EXE는 pywebview 창만 띄운다. 로컬 uvicorn·DB·.env **전부 제거** (67MB → 37MB)
- 설정: exe 옆 `A10BridgeDesktop.ini` (`[server] url`, `[user] default_usr_id`)
- `--usr-id` 인자 우선, 없으면 ini의 `default_usr_id`(현재 `4210`) 사용
- 단일 실행: 이미 떠 있으면 기존 창을 앞으로 가져옴
- **화면은 서버가 서빙한다** → 화면 수정 시 EXE 재배포 불필요, 서버만 갱신

### 6. 데스크톱 화면 (`desktop/ui/`)

웹 화면(`app/static`)이 새 디자인으로 교체된 걸 확인하고 데스크톱으로 재이식했다.
**`app/static`은 손대지 않는다**(사용자 지시). 두 벌을 각각 유지하며, 재이식 시 diff로 비교한다.
데스크톱 전용 차이는 각 JS 상단 주석에 명시해 뒀다.

오늘 추가한 기능:
- 사용자 배지(이름·지사), 지사 셀렉트(권한에 따라 잠김)
- 검색 조건: **정산 청구액 범위**, **평가액 범위**, **목적**(부분일치)
- 목록 컬럼: **목적**(`LWorkinfo`)을 감정서번호 다음에 배치. 정렬 가능
- **컬럼 폭 드래그 조절** (헤더 경계 드래그, 더블클릭 시 기본값, 브라우저에 저장)
- 상세 패널 상단에 **청구서상 수수료** 패널

수수료 계산식(실데이터 2건 대조 검증):
```
항목합(기초수수료+여비+물건조사비+토지조사비+공부발급비+기타실비+특별용역비) − 절사금액 = 수수료합계
수수료합계 + 부가가치세 = 청구금액
```
토지조사비·특별용역비·절사금액은 **0이 아닐 때만** 표시한다(합계가 맞아떨어지게).

### 7. 성능 개선

`apw_masterex`는 **15개 테이블을 조인하는 뷰**다(기준 테이블 `APW_Master` 73만행).
인덱스는 이미 충분하다 — 기준 테이블 직접 COUNT는 0.06초, 같은 조건 뷰 COUNT는 2.45초.
**인덱스를 더 걸어도 효과 없다**고 판단하고 쿼리 구조를 고쳤다.

- 입금상태 계산을 **페이징 후로** 이동 (5만건과 조인 → 30건만 계산): 5초 → 0.04초
- 건수와 목록 조회를 **동시 실행** (`_COUNT_POOL`)

| 조회 | 이전 | 현재 |
|---|---|---|
| 기본 화면(최근 7일) | 0.10초 | 0.09초 |
| 본사 전체기간(5.5만건) | 6.66초 | 2.14초 |
| 전체지사 전체기간(26.7만건) | 7.11초 | 5.36초 |
| 입금·미수금 | 0.40초 | 0.30초 |

### 8. 전표 캐시 백필

159,251줄 수집(2026-01-22 ~ 07-20, 160페이지). 이후 서버에서 30분마다 최근 7일치 자동 동기화.

백필 전에는 청구 전표가 캐시에 없어 **정상 완납 건이 '과입금'으로 잘못 표시**됐다(예: `01-2604-4-0142`).
백필 후 청구 14,660,800 = 입금 14,660,800으로 정상화됨.

## 내일 할 일 (배포)

1. **서버 배포** — `dist\A10Bridge_server.zip`(104KB)을 `192.0.2.10`의 `C:\A10Bridge`에 덮어쓰기
   ```powershell
   schtasks /end /tn A10Bridge_Server
   schtasks /run /tn A10Bridge_Server
   ```
   확인: `http://192.0.2.10:8010/desktop?usr=4210` → 목적 컬럼·수수료 패널이 보이면 성공
   (현재 서버에는 오늘 오후 변경분이 **미반영** 상태)

2. **EXE 배포** — `dist\A10BridgeDesktop_client.zip`(19MB). ini에 서버 주소·기본 사용자 세팅 완료.
   APWorks 배포에 함께 넣으면 된다. 직원 PC에 Python·ODBC·DB 계정 불필요.

3. **서버 재부팅 테스트** — `A10Bridge_Server`가 부팅 시 자동으로 뜨는지 1회 확인

### 운영 메모
- 서버 갱신 절차를 줄이려면: ① 서버에 `update.cmd` 배치 배치 ② 개발 PC가 쓸 공유 폴더 개설 — 둘 중 선택 대기 중
- `.env`가 든 zip(`A10Bridge_server.zip`)은 DB 암호·Amaranth 토큰 포함. 공유 폴더 등에 방치 금지
- 클라이언트 zip에는 비밀정보 없음
