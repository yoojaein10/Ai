# A10BRIDGE 작업 메모

작성일: 2026-07-21 (이전 메모: `HANDOFF_2026-07-20.md`)

## 한 줄 요약

입금·미수 화면을 요약 캐시로 50배 빨리 만들고, 세금계산서·엑셀 내보내기·패널/컬럼 조절을 붙였다.
APWorks 연동 축을 USR_ID → **USR_SEQ**로 바꿨고, 재무팀 엑셀 업무를 대체할 **"매출 입력"(GaPrice 승인)** 화면을 새로 만들었다.

## 현재 상태

| 항목 | 값 |
|---|---|
| 배포 방식 | **zip 안 씀.** `dist\A10Bridge_server\` 폴더를 서버 `C:\A10Bridge`에 그대로 덮어쓰기 |
| 전표 캐시 | 157만 행 (누군가 오늘 오전 2010~전체 백필, **삭제 금지** — 사용자 결정). 출처 미상 |
| 신규 테이블 | `a10_receivable_summary`(입금·미수 집계, 30분 재집계), `a10_payment_status`(APWorks 조회용, 매일 23:00), `a10_gaprice_outbox`(매출 입력 대기) |
| 스케줄러 | 기존 2개 + `A10Bridge_PaymentSync`(매일 23:00 — 입금 정리 + 매출 초안 생성) |
| 사용자 식별 | **USR_SEQ 기준** (4210은 USR_ID였음 → 이일우 USR_SEQ=813). EXE `--usr-seq`, ini `default_usr_seq` |
| 클라이언트 | `dist\A10BridgeDesktop_client.zip` (USR_SEQ 빌드, 16:40). 단일 EXE는 시작 25~60초 복불복이라 **폴더형 확정** |
| 테스트 | pytest 15개 통과 유지 |

## 오늘 한 일

1. **입금·미수 성능**: `a10_receivable_summary` 도입(전표 동기화 직후 재집계) + pyodbc NVARCHAR→varchar CAST 버그 수정 → 5초 → **0.1~0.4초**
2. **검색·목록 확장**: 입금/미수에 유치자·상태·기간(입금일/발송일, 기본 1년)·청구액·미수금 범위 검색 + 목적·발송일·순수수료·여비·기타실비 컬럼
3. **세금계산서 섹션**: 3화면 상세 패널 전표 아래 (`a10_tams_tax_cache`, appraisal_no 매칭, DISTINCT 중복 제거). ⚠️ 이 테이블은 **오늘 1회 일괄 적재된 외부 데이터** — 갱신 주기 없음, 적재 주체 확인 필요
4. **엑셀 내보내기**: 3목록 모두, 현재 검색 조건 그대로 전체(최대 10만 행) xlsx. openpyxl 의존성 추가됨
5. **UI**: 상세 패널 폭 드래그(`panel-resize.js`), 모든 표 컬럼 폭 드래그(`column-resize.js` 공통화), 전표 표를 단일 표(전표일자·전표번호·계정과목·거래처·차변·대변·적요 순)로, 초록 엑셀 버튼
6. **전표 표시 규칙**: 일괄 정산 전표는 해당 감정서 라인만(`_doc_related_lines`), Amaranth 수정 이력(취소±재기재)은 **그대로 표시** (사용자 확정)
7. **USR_SEQ 전환**: `/api/users/{usr_seq}/context`, EXE·ini·APWORKS_LAUNCH.md 갱신. ⚠️ **서버와 EXE를 같이 배포해야 함** (서버만 올리면 구 EXE의 4210이 차단됨)
8. **매출 입력 화면**(`/desktop/allocation`, 본사 전용): 야간 배치가 초안 생성(본사 감정서만, 입금일 2026-01-01+, In_Price=매출액=순수수료×`APW_Charge_IDX` iType=1 비율) → 재무팀 확인·수정 → 승인 시 `Apw_Mae_GaPrice` INSERT(0원 선등록 행 무시). 일괄 승인, 기본 조회=어제, 콤마 입력. 현재 대기 2,052건

## 내일 할 일
