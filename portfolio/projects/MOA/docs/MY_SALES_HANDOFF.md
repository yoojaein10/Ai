## 2. 기준 — 여기가 제일 중요하다

```
금액   전표(a10_voucher_cache) 401 계열 순액   ← 공급가액(수수료합계, 부가세 제외)
기간   전표일자(voucher_date)
귀속   원장 apw_masterex.Manager (유치자)
```

**부가세 제외(공급가액)다 — 2026-08-10 사용자 확정.** 한때 정산가이드 4장
1번(수수료합계+부가세)을 따라 ×1.1 을 곱했는데(2026-08-07), 회사의 실제 정산
기준을 실측으로 확인하고 되돌렸다:

- 성과상여 정산(`APW_IW_Bonus_Master`·재무팀 엑셀)의 순수수료 = **부가세 제외**
  — `In_Price`·`Basic_Susu` 모두 '부가세 포함과 일치 0건' 실측
- 기간별 매출실적 = **공급가액** (2026-07-23 재무팀 확정, TAMS 대사)
- 옛 JSP(MAECUL·유치상여 통보 Yuchi_SeongGwa)도 전부 **부가세 제외**

즉 부가세 포함이면 이 화면 혼자 다른 숫자가 된다. 덕분에 지금은 **기간별
매출실적과 원 단위로 그대로 일치**한다(×1.1 다리 불필요).

**정산가이드가 잡으려던 진짜 오류는 부가세가 아니라 청구금액이다.** 2장을 보면
"선수금 차감 후 청구액만 실적으로 잡혀 평가사 실적이 축소된다"가 문제였다.
우리는 원래 청구금액을 안 쓴다 — 401 전표는 매출 인식 시점의 총액이라 선수금이
빠지지 않는다. 실측(2026-01~07 본사): **401 순액이 원장 SuSuSum(수수료합계)과
88.1% 정확히 일치**했다. (가이드의 매출총액(부가세 포함)은 미수금·반제 화면
기준으로는 여전히 옳다 — 입금이 부가세 포함으로 들어오기 때문.)

참고(포함으로 되돌릴 일이 생기면): 세율은 예외가 없다 — 2026 본사 3,601건 중
**3,600건이 정확히 10%**, 면세(Tax=0)는 **0건**. 원장 `Tax` 칼럼을 더하는 방식은
매칭 68.2%·분할 인식 423건 때문에 안 되고, 순액 ×1.1 이 안전하다.

## 3. 유치자 칸에 여럿이 든 건 (이번 작업의 핵심)

원장 `Manager` 는 한 칸에 쉼표로 여러 명이 들어간다.
2026년 본사 기준 **51건 · 18.8억(전체 매출의 10.4%)**.

```
조근렬,강무진,김형식      ← 표기 없음
윤도,공(장재원)           ← 섞임
공(김도윤),공(이덕권)     ← 둘 다 공( )
```

그대로 두면 두 가지가 깨진다.
- `조근렬,강무진,김형식` 이 **한 사람처럼 순위에 낀다**
- 정작 세 사람은 실적이 **0으로** 나온다 (윤도·강무진·조근렬이 그랬다)

### 해결 — 배분 비율을 빌려온다

나뉜 금액은 `[apworksdw].dbo.Apw_Mae_GaPrice` 에 **사람별 한 줄씩** 들어 있다.
운영 JSP도 이 표만 본다. `_allocations()` 가 읽고 `_attribute()` 가 나눈다.

| 유치자 칸 | 처리 |
|---|---|
| `현승한` | 전액 단독 |
| `공(고세욱)` | 전액 공동 |
| 여럿 + 배분표 있음 | **비율대로 나눠 각자 단독** |
| 여럿 + 배분표 없음 | 전원 **공동** — 금액을 지어내지 않는다 |
| 여럿 + 일부만 배분표 | 있는 사람은 단독, 없는 사람은 공동 |

**균등 배분은 틀린다.** 같은 세 명인데 50/25/25 인 건도 33/33/33 인 건도 있다.
이름 순서와 비율도 무관하다 (`조근렬,강무진,김형식` 에서 첫 번째가 25%, 마지막이 50%).

### 반영 결과 (2026-01-01 ~ 07-31 본사)

```
순위 인원   94명 → 82명   (쉼표 조합 12개가 실제 사람으로 흡수)
윤도        0원 → 228,771,999   22위
강무진      0원 → 162,007,730   30위
조근렬      0원 → 162,007,730   31위
이동호      148,107,000 → 418,616,853   7위
김형식      11,765,350 → 236,061,810   21위
```

총액 검산 — 돈이 새거나 이중으로 세어지지 않는다.
```
전체 매출              18,037,230,642
단독 배분 합계         14,800,975,038
귀속자 없음(빈칸·공통)     647,263,680
공동                    2,588,991,924
```

51건 중 **44건은 비율 있음, 7건(3.9억)은 없음** → 공동으로 감.

## 7. 권한 — 본인 고정 (2026-08-07)

`emp_name` 을 **클라이언트가 정하지 않는다.** 세션(`usr_seq`)이 정한다.
요청에 남의 이름이 실려 와도 `_resolve_scope()` 가 세션 값으로 덮어쓴다.

| 대상 | 볼 수 있는 것 |
|---|---|
| 기본(전원) | 본인 실적만. 지사도 본인 소속으로 고정 |
| `a10_sales_view_grant` 명단 | 평가사 선택 가능. 단 지사 범위는 기존 권한을 그대로 따른다 |

- 목록 API(`/appraisers`)도 권한이 없으면 **본인 이름 하나만** 준다 — 목록으로 사내
  실적자 명단이 새면 바인딩이 반쪽이 된다.
- 순위는 원래대로 내 등수와 익명 평균선만 내려간다 (`_ranking`).

**이름만으로 사람을 가려도 되는 근거** (2026-08-07 실측)
```
2026 본사 유치자 표기 158종 · 단일 이름은 전부 사용자마스터 EMP 에 있다 (불일치 0)
재직 중 동명이인 18명 — 전원 소속 지사가 다르다 → (이름, 지사)면 유일하다
```

**`a10_user_permission` 에 열을 더하지 않은 이유.** 두 가지다.
1. `view_all_offices` 는 본사면 자동으로 켜진다(`users._resolve`). 재활용하면 본사
   평가사끼리 서로 실적을 다 보게 돼 바인딩이 무의미해진다.
2. 기존 표에 열을 더하면 서버에 ALTER 를 치기 전까지 `select(UserPermission)` 이
   없는 열을 읽어 **전 사용자 로그인이 깨진다.** 실제로 한 번 그렇게 만들어 보고
   `Invalid column name 'view_all_sales'` 로 확인했다. 새 표는 재배포의

## 8. 연도별 추이 (2026-08-07)

축 탭(월별·연도별)으로 갈아 끼운다. **월별과 같은 기준**이다 — 전표일자·401 순액에
같은 배분 규칙(`_attribute`)을 태운다. 두 탭이 다른 규칙을 쓰면 합이 안 맞는다.

전표 캐시는 **2010~2026, 17년** 치가 다 있다(1,723,550줄). 기본은 최근 5년.

전 인원을 훑을 필요가 없어 `m.Manager LIKE '%이름%'` 로 미리 거른다. LIKE 는
**예선일 뿐**이고 정확한 귀속은 파이썬이 다시 가른다 — '박중현' LIKE 가
'박중현우' 를 물어도 이름 비교에서 떨어진다. 실측: 박중현 241건 1.85초.

실적이 없는 해도 0으로 채워 축에 남긴다. 빠뜨리면 '쉬었다'가 안 보인다.

## 11. 순위 모수 · 공동 실적 라벨 (2026-08-07)

**순위 모수는 재직자만이다.** 운영 JSP 도 `RTRM_FL <> '1'` 로 뺀다. "지금 같이
일하는 사람들 중 내 위치"가 이 카드가 답하는 질문이다.

```
실측(2026-01~07 본사)  82명 → 76명
등수    박중현 43위 → 43위 · 이동호 7위 → 7위 · 윤도 22위 → 22위  (아무도 안 바뀜)
평균    180,537,390원 → 193,962,303원  (공급가액 기준)
```

퇴사자 6명이 전부 61위 이하라 등수는 그대로고, **실제로 정확해지는 건 평균**이다.

- `active_names()` 조회에 실패하면 거르지 않는다 — 순위 카드가 통째로 사라지는 것보다
  낫다.
- 보고 있는 사람이 퇴사자면 그 사람만은 모수에 남긴다. 재무팀이 퇴사자 실적을 열었을 때
  순위 칸만 비면 고장으로 보인다.
- 평가사 셀렉트 목록은 **안 거른다.** 퇴사자 실적을 조회할 일이 있기 때문이다.

운영 JSP 의 나머지 두 규칙은 **옮기지 않았다.**
- `Uname not in ('권오억','박재홍','조영동')` — 권오억은 재직 중이고 우리 51위다.
  빼도 등수는 안 변한다(76→75명). 임원 정책이라 우리가 정할 게 아니다.
- `Dept_Nm in ('jip','gam','sim','ju')` — 우리 화면은 '유치 실적'이지 평가사 순위표가
  아니고, 저 부서 코드가 무엇인지 확인되지 않았다.

**공동 실적 카드 라벨**을 `공동 실적 (수기정산 대상)` → `공동 건 총액 (내 몫은
수기정산)` 으로 바꿨다. 배분표가 없는 건은 참여자 **전원 화면에 건 전체 금액**이
그대로 뜬다 — 2026-01~07 본사에서 8건, 중복 표시 8.2억. 로직은 의도한 대로지만
(금액을 지어내지 않으려고) 옛 문구로는 '내 몫'으로 읽혔다.
