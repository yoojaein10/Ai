작성일: 2026-06-30  
대상 PDF: `D:\AI\Claude\Y_BankAuto\탁상\1.pdf` ~ `40.pdf`  
대상 프로시저: `dbo.SP_I_APW_TS_Master`

## 1. 결론

신규 탁상 PDF에는 자문번호가 없으므로 `@MasterID = NULL`로 호출하고, `@AppCode = '300611'`을 전달한다. 프로시저는 생성한 번호와 Identity를 `@NewMasterID`, `@NewSEQ`로 반환한다.

은행별 파서는 PDF에서 공통 접수 모델을 만든 뒤 주소 정규화와 SP 파라미터 조립을 거치는 구조가 적합하다.

분석용 40건 중 은행·주소까지 DB와 일치하는 37건을 정상 기준으로 사용했다.

- `6.pdf`: PDF는 우리은행 안성시 물건이지만 동일 MasterID의 DB 행은 국민은행 화곡동 물건이다.
- `9.pdf`: 자문번호가 `01-20260629-079.1`이며 정확한 DB 행이 없다. 접미사를 제거하면 `10.pdf`와 동일한 DB 행에 연결된다.
- `40.pdf`: `39.pdf`와 동일한 MasterID를 사용하지만 DB 행은 `39.pdf`의 새마을금고 물건이다.

따라서 기존 완료자료 대조 시에도 MasterID 외에 은행·의뢰번호·주소를 함께 검증해야 한다.

## 3. 신규 SP 호출 핵심값

| SP 파라미터 | 신규 입력값 | 근거 |
|---|---|---|
| `@MasterID` | `NULL` | 신규 번호 생성 요청 |
| `@Office` | `'10'` | 정상 기준 37건 모두 `10` |
| `@Reg_DateTime` | 실행 시각 또는 PDF 의뢰일시 | 프로시저 내부에서 날짜 변환 함수 사용 |
| `@Reg_Charge` | `NULL` | PDF 파싱값이 아니므로 미입력 |
| `@Consult_Charge` | `NULL` | PDF 파싱값이 아니므로 미입력 |
| `@AppCode` | `'300611'` | 사용자 지정 법인코드 |
| `@NewMasterID` | OUTPUT | 생성된 `01-...` 자문번호 |
| `@NewSEQ` | OUTPUT | 생성된 `TS_SEQ` |

프로시저 특성:

- `@MasterID`가 비어 있고 `@AppCode='300611'`이면 전용 분기가 없으므로 `ufn_NewCreate_Ts_DocID_ByCommon(@Office,@Reg_DateTime)`을 호출한다.
- `MasterID`는 PK/Unique이므로 중복 INSERT는 오류가 난다.
- `@Jun_Master` 입력값은 무시되고 항상 `0`이 저장된다.
- `@Score` 입력값도 무시되고 항상 `1`이 저장된다.
- `@AppCode`는 번호 생성에는 쓰지만 INSERT 컬럼에는 포함되지 않는다.
- 테이블에는 `PungCallYn`이 있지만 이 프로시저에는 해당 파라미터가 없다.
- SP의 `@Addr` 길이는 40자로 테이블의 300자보다 짧다. 긴 주소는 `Building`, `Building_Nm`, `Dong`, `Ho`로 분리해야 한다.

## 6. 입력 원칙

PDF에서 파싱하거나 PDF 값으로부터 직접 정규화할 수 있는 필드만 입력한다.

- 입력: 의뢰일시, 은행/영업점, 담당자, 전화번호, 의뢰번호, 주소, 건물·동·호, 물건종류, 구조, 건축년도, 참고사항
- 주소에서 직접 파생: `Reg`, `Eub`, `SAN`, `Addr`, `BUN1`, `BUN2`, `Building`, `Dong`, `Ho`, `Building_Nm`
- 미입력(`NULL`): 사내 사용자 코드, 평가사, 상담금액, 감정금액, 내부 상태, 내부 메모

SP는 기본값 없는 입력 파라미터도 호출 시 전달해야 하므로, 미입력 필드는 이름 지정 호출에서 명시적으로 `NULL`을 전달한다. `Jun_Master`와 `Score`는 SP 내부에서 각각 `0`, `1`로 강제된다.

## 7. 권장 처리 순서

1. Bank24 탁상 신규 행에서 PDF 저장
2. PDF 헤더로 은행 판별
3. 은행별 어댑터로 공통 접수 모델 생성
4. PDF 은행명과 영업점명으로 `CustName` 구성
5. 주소 파싱 및 `APW_RegHist`로 `Reg`, `Eub` 조회
6. 의뢰번호 기준 사전 중복 확인
7. PDF 파싱값 외 파라미터는 `NULL`로 구성
8. `SP_I_APW_TS_Master` 호출
9. `NewMasterID`, `NewSEQ` 수신 및 결과 표시
10. 실패 시 트랜잭션 롤백 및 PDF 보존
